## 💡 Overview

In traditional algorithmic trading, turning a trading idea into a live system requires writing boilerplate indicator math, handling exchange-specific edge cases, wiring up backtesters, and hand-crafting state machines for risk control.

**PrompTrading bridges this gap:**

> *You provide the market hypothesis, risk appetite, and trading concept — PrompTrading handles strategy implementation, closed-loop backtest verification, sandbox isolation, and institutional-grade live execution.*

Tell PrompTrading:
> *"Build an intraday breakout strategy on BTC/USDT 15m candles with a volume surge filter, 2.5x ATR trailing stop, and dynamic profit targets based on recent swing highs."*

Within minutes, the built-in **Tau coding agent** drafts standard-compliant Python strategy code, launches throwaway Docker containers to backtest it against real historical market data, analyzes the resulting Sharpe ratio and drawdowns, self-repairs any defects, and prepares the strategy for one-click live execution behind a multi-layered risk engine.

## ✨ Key Features

- 🤖 **Prompt-to-Alpha Coding Agent (Tau Engine)**  
  Driven by [Tau](https://github.com/huggingface/tau) (`tau-ai`), the autonomous coding agent writes, inspects, and refines executable Python strategies inside versioned sandboxes (`versions/<version_id>/`).
- 🔁 **Closed-Loop Autonomous Backtesting**  
  The agent doesn't guess if the strategy works — it executes backtests against real historical bars in isolated subprocesses, evaluates metrics (Sharpe ratio, max drawdown, win rate, Sortino), and iterates automatically until the strategy meets performance criteria.
- 🛡️ **Defense-in-Depth Risk Engine**  
  Production-grade risk management protecting your capital on live markets:
  - **9 Invasive Pre-Trade Checks** (max order size, leverage caps, price sanity, balance validation, etc.)
  - **Profit-Activated Trailing Stops**
  - **Dynamic TP/SL** (Support/Resistance + ATR volatility-based triggers)
  - **Automated Exchange Reconciliation** & position drift detection
  - **Snowflake Order ID Management** for zero duplicate fills
- 🐳 **Ephemeral Docker Sandbox Isolation**  
  Untrusted LLM-generated code **never** runs inside the core API process. Strategy generation and backtesting execute in disposable, resource-constrained Docker containers with network guards.
- ⚡ **High-Speed Parquet Market Data Cache**  
  Vectorized backtesting backed by a shared Parquet cache covering major crypto exchanges and US equities. Gap-aware incremental syncing eliminates redundant network calls.
- 🖥️ **Modern Web Cockpit**  
  A responsive React 18 + Tailwind SPA providing conversational strategy iteration, workspace code diffs, interactive equity curves, real-time position streaming, and instant live/demo toggles.
- 🔒 **Encrypted Credentials at Rest**  
  Exchange API keys, secrets, and passphrases are Fernet-encrypted in the database at rest.
- 🔭 **Enterprise Observability**  
  Optional integration with Langfuse for prompt auditing, token usage tracking, and model latency monitoring.

## 🚀 Quick Start

Get PrompTrading up and running in under 3 minutes with Docker Compose.

### Prerequisites

- **Docker** and **Docker Compose** (v2+)
- An API key for any OpenAI-compatible LLM provider (DeepSeek, OpenAI, etc.)
- Python 3 (to generate the encryption key)

### 1. Clone & Setup Environment

```bash
git clone https://github.com/xlabsg/prompTrading.git
cd prompTrading
cp infra/compose/.env.example infra/compose/.env
```

### 2. Generate Credentials Encryption Key

PrompTrading uses a Fernet symmetric key to encrypt exchange credentials at rest:

```bash
python3 -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Copy the generated key and set it in `infra/compose/.env`:

```env
TRADING_API_ENCRYPTION_KEY=<your-generated-fernet-key>
LLM_API_KEY=<your-llm-api-key>
```

### 3. Launch the Stack

```bash
./infra/compose/update.sh
```

Once containers finish initializing, access the services:

| Service | Address | Description |
| :--- | :--- | :--- |
| **Web Console** | [http://localhost:3000](http://localhost:3000) | Full strategy studio, backtester & live cockpit |
| **API Backend** | [http://localhost:8000](http://localhost:8000) | FastAPI application server |
| **API Docs (Swagger)** | [http://localhost:8000/docs](http://localhost:8000/docs) | Interactive API documentation |

> **Helpful CLI Flags:**  
> - Rebuild specific services: `./infra/compose/update.sh api worker`  
> - Skip image rebuild: `./infra/compose/update.sh --no-build`  
> - Skip remote image pulls: `./infra/compose/update.sh --no-pull`

## ⚙️ Configuration

All runtime options are managed via `infra/compose/.env`.

### Core Requirements

| Variable | Required | Description |
| :--- | :---: | :--- |
| `TRADING_API_ENCRYPTION_KEY` | **Yes** | 32-byte Fernet key encrypting exchange credentials at rest. |
| `LLM_API_KEY` | **Yes** | API key for your chosen LLM provider. |

### LLM Provider Settings

| Variable | Default | Description |
| :--- | :--- | :--- |
| `LLM_PROVIDER` | `deepseek` | Provider identifier: `deepseek`, `openai`, `anthropic`, or OpenAI-compatible gateway. |
| `LLM_BASE_URL` | *provider default* | Base URL for API completions (e.g. `https://api.deepseek.com`, `https://api.openai.com/v1`). |
| `LLM_MODEL` | `deepseek-chat` | Model name used by the Tau coding agent. See recommended models below. |
| `LLM_TEMPERATURE` | `0.2` | Sampling temperature for strategy code generation. |
| `LLM_HTTP_TIMEOUT_S` | `300` | Request timeout in seconds for LLM inference calls. |
| `LLM_FALLBACK_ON_ERROR` | `false` | Emit template strategy if agent encounters unrecoverable errors. |

#### Recommended Models

| Provider | Recommended `LLM_MODEL` | Highlights |
| :--- | :--- | :--- |
| **Anthropic** | `claude-fable-5-1`<br>`claude-opus-5`<br>`claude-sonnet-5` | Flagship agentic generation: `claude-fable-5-1` for complex long-horizon strategy reasoning (1M context); `claude-opus-5` for deep quantitative coding; `claude-sonnet-5` for balanced speed. |
| **DeepSeek** | `deepseek-v4-pro`<br>`deepseek-v4-flash`<br>`deepseek-chat` | SOTA code synthesis: `deepseek-v4-pro` with adaptive reasoning/thinking modes for quantitative algorithms at maximum cost efficiency. |
| **OpenAI** | `gpt-5`<br>`o3`<br>`o3-mini` / `gpt-4.5` | Frontier reasoning: `gpt-5` for general orchestration; `o3` / `o3-mini` for advanced mathematical logic and multi-step quantitative backtest optimization. |
| **OpenAI-Compatible** *(OpenRouter, Qwen, Gemini)* | `google/gemini-2.5-pro`<br>`qwen-3-coder`<br>`qwen-2.5-coder-32b-instruct` | Enterprise proxies and private models configured via custom `LLM_BASE_URL`. |

> Provider-specific environment variables like `ANTHROPIC_API_KEY`, `DEEPSEEK_API_KEY`, and `OPENAI_API_KEY` are automatically detected and honored.

### Database & Storage

| Variable | Default | Description |
| :--- | :--- | :--- |

## 🏗️ Repository Layout

PrompTrading is structured as a modular Monorepo:

```
prompTrading/
├── apps/
│   └── web/                   # React 18 + Vite dashboard (TypeScript, Tailwind, Radix UI)
├── services/
│   ├── api/                   # FastAPI backend (REST & WebSocket endpoints)
│   └── worker/                # Async task worker (spawns ephemeral Docker containers)
├── packages/
│   ├── agent/                 # Strategy coding agent domain layer (Tau runner_v2, backtest tool)
│   ├── backtest/              # Vectorized backtesting engine & performance artifact generator
│   ├── control_plane/         # Shared SQLAlchemy models, enums, versioning factory
│   ├── data/                  # Market data providers (crypto & US equities) & Parquet cache
│   ├── live_trading_sdk/      # Strategy developer SDK (LiveStrategy & Broker protocols)
│   ├── okx_sdk/               # Exchange connectivity & execution client
│   └── risk_engine/           # 9-check pre-trade risk engine, trailing stop, reconciliation
└── infra/
    ├── compose/               # Docker Compose configurations (dev, prod, e2e)
    └── images/                # Dockerfile definitions for ephemeral agent & backtest containers
```

## ✍️ Strategy Authoring SDK

Strategies in PrompTrading implement the clean, decoupled protocols defined in `packages/live_trading_sdk/`:

```python
from live_trading_sdk import LiveStrategy, StrategyContext, Bar, Broker

class DynamicBreakoutStrategy(LiveStrategy):
    async def initialize(self, ctx: StrategyContext) -> None:
        ctx.subscribe("BTC-USDT-SWAP", interval="15m")

    async def on_bar(self, ctx: StrategyContext, broker: Broker, bar: Bar) -> None:
        # Instead of placing raw exchange orders, express trading intent:
        if bar.close > ctx.get_indicator("upper_band"):
            await broker.set_target_allocation("BTC-USDT-SWAP", target_percent=0.5)
        elif bar.close < ctx.get_indicator("lower_band"):
            await broker.set_target_allocation("BTC-USDT-SWAP", target_percent=0.0)

    async def on_error(self, ctx: StrategyContext, error: Exception) -> None:
        ctx.logger.error(f"Strategy error encountered: {error}")
```

Because strategies interact with an abstract `Broker` protocol rather than raw exchange sockets, the **exact same strategy code runs identically in historical vector backtesting and live trading**.
