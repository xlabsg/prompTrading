# Trading SDK 设计文档

## 概述

Trading SDK 是一个通用的 live trading 基础设施，提供完整的风险控制、订单管理、仓位监控等功能。设计参考了 `trading_view_script` 仓库的优秀实践，并结合现有项目的架构进行了优化。

## 设计原则

### 1. 安全优先
- **侵入式风险控制**：所有订单在下单前必须通过风险验证
- **强制止损**：可配置为强制要求设置止损
- **多层防护**：仓位限制、杠杆限制、每日亏损限制、最大回撤限制

### 2. 可观测性
- 所有状态变化都有日志记录
- 完整的交易统计指标
- 对账机制确保数据一致性

### 3. 容错性
- 状态持久化（Redis + PostgreSQL）
- 重启恢复
- 对账机制
- 陈旧订单清理

### 4. 可扩展性
- 适配器模式支持多交易所
- 插件化的止损策略
- 混合模式的 TP/SL 计算

### 5. 性能
- 限流保存（避免频繁写入）
- 缓存机制（工具信息、账户配置）
- 线程安全

## 核心架构

### 关键设计决策

#### 1. 侵入式风险控制 vs 建议式
**选择**：侵入式
**理由**：风控应该是硬约束，不应该允许绕过。如果风险验证失败，直接拒绝订单，避免潜在的大额亏损。

#### 2. 移动止损的激活和距离
**支持的模式**：
- 激活：利润百分比、利润金额、立即激活
- 距离：百分比、ATR 倍数、固定金额

**理由**：不同策略有不同需求，提供灵活配置。

#### 3. TP/SL 的计算方式
**支持的模式**：
1. 动态计算（支撑阻力 + ATR）
2. 手动设置
3. 混合模式（策略可选择）

**理由**：既提供智能默认，又允许策略完全控制。

#### 4. 订单类型的抽象
**设计**：SDK 定义通用类型，适配器负责转换

**理由**：
- 便于跨交易所
- 简化策略代码
- 集中处理差异

#### 5. 状态持久化策略
**设计**：Redis（热存储）+ PostgreSQL（冷存储）

**理由**：
- Redis：快速读写，适合实时状态
- PostgreSQL：持久化，适合历史查询
- 双写保证数据安全

#### 6. 对账频率
**正常模式**：60 秒
**异常触发**：立即对账
**启动时**：全量对账

**理由**：平衡性能和数据一致性。

#### 7. 单策略单账户
**选择**：简化设计，单策略对应单账户

**理由**：
- 避免复杂的资金分配
- 简化风险隔离
- 逐仓模式提供天然隔离

## 核心组件设计

### 1. RiskValidator（风险验证器）

**职责**：下单前的风险检查

**检查项**：
1. 余额是否足够
2. 是否超过最大仓位
3. 杠杆是否超限
4. 止损是否有效
5. 风险回报比
6. 每日亏损限制
7. 最大回撤
8. 订单大小
9. 是否允许对冲

**关键方法**：
- `validate_order()`: 主验证入口，返回 `RiskCheckResult`
- `reset_daily_stats()`: 每日重置统计

**设计亮点**：
- 每日统计自动重置（检测日期变化）
- 支持手动重置
- 详细的违规信息

### 2. PositionManager（仓位管理器）

**职责**：TP/SL 的计算和管理

**支持的模式**：
- 动态模式：基于支撑阻力 + ATR
- 手动模式：策略自定义
- 混合模式：策略可切换

**关键方法**：
- `calculate_tpsl()`: 计算 TP/SL
- `set_manual_tpsl()`: 设置手动 TP/SL
- `enable_dynamic_tpsl()`: 启用动态计算
- `extract_support_resistance()`: 从 K 线提取支撑阻力
- `calculate_atr()`: 计算 ATR

**设计亮点**：
- 自动验证风险回报比
- 支持 S/R 优先，ATR 缓冲，兜底百分比
- 状态可持久化

### 3. StopLossManager（止损管理器）

**职责**：管理多种止损策略

**支持的策略**：
- `FixedStopLoss`: 固定止损
- `TrailingStopLoss`: 移动止损

**移动止损特性**：
- 激活条件可配置（利润 %、利润 $、立即）
- 距离可配置（百分比、ATR、固定 $）
- 止损只能向有利方向移动
- 状态可持久化

**关键方法**：
- `register_position()`: 为仓位注册策略
- `update()`: 更新止损状态
- `should_trigger()`: 检查是否触发
- `get_stop_price()`: 获取止损价格

**设计亮点**：
- 策略模式（易于扩展）
- 每个仓位独立策略
- 线程安全

### 4. OrderManager（订单管理器）

**职责**：订单生命周期管理

**功能**：
- Snowflake ID 生成（唯一性保证）
- 订单追踪（本地 ID、客户端 ID、交易所 ID）
- 陈旧订单检测
- 自动清理已完成订单

**关键方法**：
- `add_order()`: 添加订单
- `get_order()`: 获取订单（多种 ID）
- `update_order()`: 更新订单状态
- `get_stale_orders()`: 获取陈旧订单
- `cleanup_finished_orders()`: 清理已完成订单

**Snowflake ID 设计**：
```
64 位:
- 41 位: 时间戳（毫秒，自 2024-01-01）
- 10 位: 节点 ID（主机 hash ^ PID）
- 12 位: 序列（同毫秒内递增）

格式: {prefix}{direction}{snowflake_base36}
示例: mystrategyL5f3k2x
```

**设计亮点**：
- 全局唯一（跨机器）
- 时间有序
- 包含策略信息（前缀）
- OKX 兼容（32 字符限制）

### 5. Reconciler（对账器）

**职责**：与交易所定期同步状态

**对账内容**：
- 订单状态（status, filled_size, avg_fill_price）
- 仓位大小（size, entry_price）

**对账逻辑**：
1. 从交易所获取最新数据
2. 与本地状态比对
3. 记录差异
4. 返回差异报告

**差异处理**：
- 订单缺失：交易所没有，本地有（可能已取消）
- 状态不一致：成交数量、状态不匹配
- 价格偏差：平均成交价不一致

**设计亮点**：
- 非侵入式（只检测，不自动修复）
- 详细的差异报告
- 统计信息（对账次数、错误次数）

### 6. DrawdownTracker（回撤追踪器）

**职责**：监控最大回撤和每日亏损

**追踪指标**：
- 历史最高权益
- 当前回撤（金额和百分比）
- 最大回撤（金额和百分比）
- 每日起始权益
- 每日盈亏（金额和百分比）

**关键方法**：
- `update()`: 更新回撤统计
- `is_max_drawdown_exceeded()`: 检查是否超过最大回撤
- `is_daily_loss_exceeded()`: 检查是否超过每日亏损
- `reset_daily_stats()`: 重置每日统计

**设计亮点**：
- 自动检测日期变化
- 支持百分比和金额限制
- 状态可持久化

### 7. ExchangeAdapter（交易所适配器）

**职责**：统一不同交易所的 API 差异

**抽象方法**：
- 订单操作：`place_order()`, `cancel_order()`, `get_order()`
- 仓位查询：`get_positions()`, `get_balance()`
- 行情获取：`get_ticker()`
- 杠杆设置：`set_leverage()`
- 规范化：`normalize_symbol()`, `normalize_price()`, `normalize_size()`
- 转换：`translate_order_type()`, `translate_order_side()`

**OKX 适配器实现**：
- 包装现有的 `okx_sdk.OKXClient`
- 自动处理价格和数量规范化
- 支持附加止盈止损订单

**设计亮点**：
- 适配器模式（易于扩展）
- 统一接口
- 自动规范化

## 数据流

### 下单流程

```
1. 策略生成信号
   ↓
2. 创建 OrderSpec
   ↓
3. 计算 TP/SL (PositionManager)
   ↓
4. 风险验证 (RiskValidator)
   ├─ 通过 → 继续
   └─ 拒绝 → 返回错误
   ↓
5. 下单 (ExchangeAdapter)
   ├─ 规范化价格和大小
   ├─ 转换订单类型
   └─ 调用交易所 API
   ↓
6. 订单追踪 (OrderManager)
   ├─ 生成 Snowflake ID
   ├─ 添加到内存
   └─ 持久化到数据库
   ↓
7. 注册止损策略 (StopLossManager)
   └─ 为仓位创建止损策略
```

### 监控循环

```
每 5 秒:
1. 获取最新仓位 (ExchangeAdapter)
   ↓
2. 更新移动止损 (StopLossManager)
   ├─ 检查激活条件
   ├─ 更新追踪价格
   └─ 检查触发条件
   ↓
3. 计算 PnL (PnLCalculator)
   ├─ 未实现盈亏
   └─ 已实现盈亏
   ↓
4. 更新回撤统计 (DrawdownTracker)
   ├─ 检查最大回撤
   └─ 检查每日亏损
   ↓
5. 如果触发止损 → 执行平仓
   ↓
6. 广播 WebSocket 更新
```

### 对账流程

```
每 60 秒 (或异常时立即):
1. 获取本地订单
   ↓
2. 获取交易所订单 (ExchangeAdapter)
   ↓
3. 比对订单 (Reconciler)
   ├─ 状态差异
   ├─ 成交差异
   └─ 价格差异
   ↓
4. 记录差异日志
   ↓
5. 返回差异报告
   └─ 由上层决定如何处理
```

## 性能优化

### 1. 缓存机制
- **工具信息缓存**（5 分钟 TTL）
- **账户配置缓存**（30 秒 TTL）

### 2. 限流保存
- 状态保存限流（默认 1 秒）
- 避免频繁写入数据库

### 3. 线程安全
- 订单管理器：`threading.Lock`
- 状态存储：文件锁（如需文件备份）

### 4. 批量操作
- 支持批量查询订单
- 批量清理已完成订单

## 可扩展性

### 1. 新增交易所
1. 继承 `ExchangeAdapter`
2. 实现所有抽象方法
3. 处理交易所特定的差异

### 2. 新增订单类型
1. 在 `OrderType` 枚举中添加
2. 在适配器中实现转换逻辑

### 3. 新增止损策略
1. 继承 `StopLossStrategy`
2. 实现所有抽象方法
3. 在 `StopLossManager` 中注册

### 4. 新增风控规则
1. 在 `RiskValidator` 中添加检查方法
2. 在 `validate_order()` 中调用

## 总结

Trading SDK 是一个**生产就绪**的 live trading 基础设施，融合了参考仓库的优秀实践和现有项目的架构优势。通过侵入式风险控制、完整的订单管理、准确的 PnL 计算和可靠的对账机制，为算法交易提供了坚实的基础。

**核心优势**：
1. **安全可靠**：多层风控、状态持久化、对账机制
2. **易于使用**：清晰的 API、详细的文档、完整的示例
3. **高性能**：缓存优化、限流保存、线程安全
4. **可扩展**：适配器模式、策略模式、插件化设计

**适用场景**：
- 算法交易平台
- 量化投资系统
- 自动化交易机器人
- 交易策略回测和实盘

总代码量约 2200 行，模块清晰，易于维护和扩展。
